5. DATABASE CHANGES:
   - Extended `user` schema in Mongoose (`backend/models/auth.js`) with:
     * `role`: String enum ['user', 'admin'] (default 'user')
     * `status`: String enum ['active', 'suspended'] (default 'active')
     * `phone`: String (optional)
     * `reputation`: Number (default 0)
     * `subscription`: Subdocument { plan: ('free'|'bronze'|'silver'|'gold'), active: Boolean, startDate: Date, endDate: Date }
     * `preferredLanguage`: String (default 'en')
     * Security/OTP fields: `resetOtp`, `resetOtpExpire`, `resetRequestCount`, `resetRequestDate`, `languageOtp`, `languageOtpExpire`, `loginSecurityOtp`, `loginSecurityOtpExpire`
   - Added indexes on `email`, `role`, and `status`.

6. API / ROUTES / ENDPOINTS ADDED OR CHANGED:
   - GET `/api-health`: Added environment and timestamp metadata.
   - POST `/user/signup`: Sanitized response (no password/OTP returned), updated to accept `phone`.
   - POST `/user/login`: Blocks suspended accounts (returns 403 Forbidden), returns full user profile minus sensitive fields.
   - GET `/user/getallusers`: Excludes sensitive fields (`-password -resetOtp -languageOtp -loginSecurityOtp`).
   - PATCH `/user/update/:id`: Enforces authorization check (users can only edit their own profile unless admin).

7. UI / PAGES / COMPONENTS ADDED OR CHANGED:

8. AUTHENTICATION / AUTHORIZATION / SECURITY MEASURES:
   - Password Hashing: Bcrypt salt rounds = 12.
   - JWT Secret: Handled via environment configuration (`config.jwtSecret`).
   - Account Status Guard: Suspended accounts are rejected on login and protected routes with 403 Forbidden.
   - Response Sanitization: Passwords and OTP tokens are explicitly excluded from API responses using standard helper sanitization and Mongoose `.select('-password ...')`.
   - Ownership Guard: Users cannot mutate other users' profiles unless possessing admin role.
   - Cryptographic OTPs: Uses `crypto.randomInt` rather than `Math.random()`.

9. PACKAGES / DEPENDENCIES ADDED:

11. HOW THE FEATURE WORKS:
    - Backend startup calls `validateEnv()` to check required variables.
    - User registration or login returns a JWT token along with sanitized user attributes (`role`, `reputation`, `subscription`, `preferredLanguage`).
    - Incoming requests to protected routes pass through `auth` middleware, which verifies JWT signature, retrieves user from MongoDB, and confirms account status is active.
    - Admin-only routes can apply `requireAdmin` middleware.
